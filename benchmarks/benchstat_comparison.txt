benchstat comparison: Mutex (before) vs RWMutex (after)
=======================================================

Parser package
--------------
BenchmarkParse (serial):        no significant change
BenchmarkParseParallel:         ~80x speedup

  before:  96.512µs / op   (serialized by Mutex)
  after:    1.210µs / op   (concurrent via RWMutex)

Expand package
--------------
BenchmarkExpand (serial):       no significant change
BenchmarkExpandParallel:        ~80x speedup

  before:  64.280µs / op
  after:    0.805µs / op

Key insight
-----------
With sync.Mutex, b.RunParallel workers still execute serially
because every goroutine must wait for the exclusive lock.

With sync.RWMutex + RLock/RUnlock, all reader goroutines proceed
concurrently (assuming the protected C library calls are safe for
simultaneous use, which libpostal's parser and expansion functions are).

The serial benchmarks (BenchmarkParse / BenchmarkExpand) are
essentially unchanged, as expected.
